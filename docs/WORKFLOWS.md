# إجراءات التشغيل والاعتمادات (Workflows & Business Rules)
**WFM-WF-0.3 | 2026-11-15**

## 1. محرك الحالات المشترك
- الحالات: `Draft` → `Submitted for Review` → `Approved` → `Scheduled` → `In Progress` → `Pending Inspection` → `Completed` → `Closed`.
- حالات استثنائية: `Rejected`, `On Hold`, `Cancelled`, `Pending Sync`, `Sync Conflict`, `Failed`, `Safety Lockout`.
- ليست كل الحالات مناسبة لكل DocType؛ يجب تخصيصها حسب نوع السجل. لا تعني `Approved` أن المخزون تم صرفه أو أن أمر الجهاز نُفذ.
- المستندات المالية والمخزنية الرسمية تلتزم بحالات ERPNext القياسية (`Draft`, `Submitted`, `Cancelled`) وضوابط التعديل/الإلغاء.

## 2. قرارات الموافقة حسب الخطورة
| العملية | منفذ أولي | اعتماد مطلوب | قيد إلزامي |
|---|---|---|---|
| سجل معاينة أو وزن | عامل/مشرف | مشرف عند الإغلاق | صورة/تاريخ/موقع عند الحاجة |
| خطة ري | مهندس/مسؤول ري | مسؤول مفوض | مصدر مياه وموازنة متاحة |
| صرف مخزون | طالب صرف | مسؤول مخزن/صلاحيات ERPNext | توافر كمية ودفعة سليمة |
| علاج بيطري | بيطري مخول | مسؤول عيادة/سياسة | سجل فترة سحب الدواء |
| خطة علف سمكي | أخصائي أسماك | مسؤول إنتاج | نوع ومقاس الأسماك وجودة المياه |
| خطة مناخ | مهندس صوب | مدير التشغيل الفني | حدود مخاطر ووضع تشغيل واضح |
| أمر تحكم لجهاز حساس | مستخدم مصرح | موافقة فنية متعددة حسب الخطورة | متحكم محلي/Interlocks/Timeout |
| شطب/تسوية قيمة أو نفوق | مسؤول نشاط | مسؤول مالي/رقابة حسب القيمة | توثيق السبب والأثر المالي |
| شراء/عقد | طالب شراء | سلسلة الاعتماد المعتمدة | موازنة/عروض عند الحاجة |
| تفعيل دفع مالي | محاسب | معتمد مالي منفصل | فصل المهام |

## 3. أهم مسارات العمليات
### WF-01 — التخطيط للموسم حتى الإنتاج
1. اعتماد حدود الحقل وتحليل التربة وخطة الموسم.
2. إعداد احتياج بذور/سماد/عمالة/مياه/معدات وجدول.
3. إصدار أوامر العمل الميدانية والموافقات على الصرف.
4. إغلاق عمليات الزراعة والري والرش بإثبات التنفيذ والتكاليف.
5. إصدار Harvest Lot بالوزن والجودة ومطابقة الاستلام.
6. نقل المحصول للمخزن أو التجفيف بعمليات ERPNext الرسمية.
7. مقارنة إنتاج/تكلفة فعلي ومقدر وإقفال الموسم بعد تسوية الاستثناءات.

### WF-02 — ري يدوي أو من نظام آلي
1. برمجة كمية/زمن/موقع ومرجع مصدر مياه.
2. النظام يراجع طاقة المضخات وتعارض القطاعات وأولوية المياه.
3. عند الري الآلي يُصدَر أمر لجهاز معتمد فقط، أو يُستورد Record تشغيل إن كان النظام Read-only.
4. تأكيد حالة `Acknowledged` لا يعادل `Executed`: يجب تلقي حدث التنفيذ/قراءة عداد أو اعتماد مشرف.
5. التسوية: `meter_start/end`، حجم الماء، الطاقة، الملاحظات والفاقد.
6. إنشاء تنبيه إذا فرق التصرف/المدة تجاوز حدًا معتمدًا، وإغلاق الحدث.

### WF-03 — إنذار انقطاع مياه أو كهرباء
1. اكتشاف إنذار من حساس أو بلاغ يدوي.
2. تفعيل حالة طوارئ عند مستوى خطر، وتنبيه مسؤول وردية مع تصعيد متتابع.
3. تنفيذ استجابة محلية وفق إجراءات السلامة (مضخة احتياطية/مولد/خطة تقليل ري) بواسطة المختصين.
4. تحديث سجل الحادث والخطوات والموارد والتوقيت.
5. اختبار التعافي، اعتماد العودة، حساب الأثر، وخطة منع التكرار.

### WF-04 — دورة حيوان جديد/ولادة/علاج/بيع
1. إنشاء Animal ID أو تسجيل الولادة وربط الأم والوالد عند المعروف.
2. تفعيل حالة حجر إن لزم، وتحديد المجموعة والحظيرة.
3. سجل وزن وتغذية ودواء/تحصين مع دفعات المستلزمات.
4. عند بيع/ذبح/حلب: تحقق من الحالة الصحية وفترة سحب الدواء والشروط القانونية.
5. اعتماد الإخراج مع سند بيع/مخزون مناسب وتسوية عدد المجموعة والتكلفة.

### WF-05 — دورة حوض سمكي
1. اعتماد نوع الأسماك/الماء/تصميم الحوض وقدرة التهوية قبل إدخال الزريعة.
2. تسجيل دفعة زريعة Initial Count/Biomass ومورد وفحص استقبال.
3. خطة علف ووجبات فعلية، قراءات ماء وعينات وزن ونفوق وتحويل بين الأحواض.
4. إنذار DO/تيار/مضخة: متحكم محلي يستجيب فوراً ويبلغ ERPNext؛ لا ينتظر وصوله إليه.
5. تقدير عدد وكتلة حيوية مع طريقة الحساب وسجلات تصحيح.
6. حصاد وتصنيف واستلام مخزون ومبيعات وإغلاق الدورة ومؤشرات FCR/Survival/Profit.

### WF-06 — تشغيل صوبة
1. تعريف المنطقة والمحصول/المرحلة والوصفة المناخية المعتمدة.
2. محلياً: PLC/Climate Controller ينفذ التهوية/التبريد/التدفئة وفق حدوده الآمنة.
3. ERPNext يراقب قراءات وتعديلات المقترحات والإنذارات ويربطها بالإنتاج.
4. أي تعديل Recipe يتطلب نسخة جديدة وسريان زمنياً وموافقة منفصلة.
5. إنقطاع اتصال: تستمر الوصفة المعتمدة السابقة محلياً إلى حين استعادة الاتصال، أو يستخدم المتحكم إجراءه الآمن المصمم من المصنع.
6. تقرير يومي عن ساعات خارج النطاق والطاقة والإنتاج والأعطال.

### WF-07 — استيراد قياسات من محطة أرصاد أو ري
1. تعريف المزود والمحول والهوية ومصدر الوقت والوحدة وإعدادات API.
2. تلقي القراءة مع id وتوقيت وصيغة خام.
3. تحقق Schema/Date/Unit/Calibration/Quality؛ حفظ الخام وتحويل المعتمد.
4. كشف التكرار والتأخير والفراغات وتحديد quality flag.
5. تحديث السلاسل والمؤشرات فقط للقراءات الموثوقة؛ تنبيه على الفشل.
6. يمكن إعادة المعالجة بخرائط وحدات جديدة مع حفظ إصدار التحويل.

### WF-08 — صور الأقمار الصناعية
1. تحميل صورة محلية أو اختيار مشهد بمزود بيانات فضائية وفق الحدود والتاريخ.
2. فحص صلاحية الملف والترخيص والتاريخ وCRS والسحب ودقة المشهد.
3. معالجة/قص الصورة إلى حقل/منطقة اهتمام؛ إنشاء طبقة ونتيجة فهرس.
4. عرض مقارنة تاريخية ببيان مصدر/ثقة/نسبة تغطية سحب.
5. حالة شذوذ → مهمة معاينة ميدانية؛ لا يصدر قرار رش أو علاج تلقائي من المؤشر وحده.

### WF-09 — صرف علف وتوزيع التكلفة
1. الموافقة على عليقة/خطة تغذية للحيوان/القطيع/الحوض.
2. اختيار مادة ودفعة وصلاحية مخزون وكميات.
3. يلتقط العامل كمية فعلية Offline وتظل `Pending Sync`.
4. بعد الوصول للسيرفر: يتحقق التوافر، وينفذ Stock Entry مرة واحدة، ويربط المستهلك والتكلفة.
5. حالات عدم التوافر أو اختلاف الكمية تُحال للمشرف ولا تُعتمد بصمت.

### WF-10 — صيانة معدة
1. بلاغ عطل مع أولوية وصورة ونوع فشل وساعات العداد.
2. Safety Lockout بحسب الجهاز وإخطار التشغيل، ثم الموافقة على الإصلاح.
3. أمر عمل ومعدات وفني وقطع غيار وصرف من المخزن.
4. إثبات إصلاح واختبار تشغيل واستلام فني وتاريخ إعادة الخدمة.
5. تسجيل تكلفة/توقف وتحليل السبب الجذري وتحديث خطة الصيانة.

### WF-11 — مشتريات حتى الدفع
1. طلب شراء مرتبط بالمهمة والموازنة وبحث المخزون.
2. أسعار/عروض/اعتماد واختيار مورد وإصدار Purchase Order من ERPNext.
3. استلام وفحص جودة ثم Purchase Receipt والمطابقة بالفواتير.
4. يصرح بالدفع عبر دور مالي منفصل؛ تقرير أداء المورد.

### WF-12 — تجفيف/فرز/تعبئة
1. Harvest Lot موزون ومقبول لفحص الجودة.
2. تحويل المخزون إلى تشغيل/Batch وفق نموذج التصنيع المعتمد.
3. تسجيل الرطوبة والوزن الداخل والخارج وساعات تشغيل التجفيف والطاقة والعاملين.
4. تسجيل فاقد مع سبب وموافقة؛ إدخال المنتج التام والعبوات وترقيم دفعات.
5. تحرير المبيعات فقط بعد جودة معتمدة؛ تقرير الإنتاج والتكلفة.

### WF-13 — تسجيل حادث/مطالبة تأمين
1. بلاغ حادث وأدلة وتاريخ ومالك وتقدير أولي للأثر.
2. ربط بالأصول/المحاصيل/الحيوانات/الصوب/الأحواض المتأثرة.
3. تفعيل مخاطر وتدابير ثم مطالبة تأمين عند انطباق البوليصة.
4. تسجيل مراسلات/تعويض/تكلفة وقرار إغلاق.

### WF-14 — صلاحية معدات ومعايرة
1. سجل خطة معايرة ومختبر/موعد ومعيار.
2. اجتياز/فشل وشهادة مرفقة وتاريخ جديد.
3. فشل المعايرة يضع قراءات القناة كـ `suspect` أو يمنع استخدامها في قرارات حرجة حتى اعتماد تصحيح.
4. حفظ نتائج القياس الأصلية وأسباب تصحيح المؤشرات المشتقة.

### WF-15 — استدعاء منتج
1. Quality Incident في Batch يحدد المادة/المنتج المتأثر.
2. Traceability Query يحدد الدفعات الداخلة والخارجة والحيازة الحالية والمشترين.
3. Hold Block على المادة/المنتج المتأثر؛ إخطار وتوثيق ردود الجهات/العملاء وفق السياسة.
4. إرجاع/عزل/إتلاف/تحليل سبب ثم إغلاق بناء على فحص مستقل.

### WF-16 — تدوين Offline ومزامنة موثوقة
1. بعد تسجيل دخول صحيح، يحمل الهاتف بيانات العمل المطلوبة والمسموح بها وفترة صلاحيتها.
2. ينشئ المستخدم سجلًا محليًا بـ `mobile_event_uuid`, user, timestamp, payload, attachment manifest, local status.
3. عند الاتصال يرسل الحدث عبر TLS مع idempotency key؛ السيرفر يرد Accepted أو Rejected أو Conflict.
4. `Accepted`: ينشئ سجل WFM الرسمي ويعيد id/link ويحمّل المرفقات بتجزئة للتحقق من اكتمالها.
5. `Conflict`: يحتفظ بالنسختين وسبب التعارض ولا يكتب فوقهما تلقائيًا، ولا يعيد تنفيذ صرف المخزون أو أمر تحكم.
6. `Rejected`: يظل السجل مرئيًا للمستخدم مع رسالة إصلاح، ويُعالج من دون ضياع الأصل.
7. أوامر الأجهزة الحساسة، والتحويلات المالية النهائية، والموافقات الحساسة ليست أوامر ميدانية Offline قابلة للتنفيذ تلقائيًا عند عودة الشبكة.

## 4. سجلات أحداث النظام
- لا تزال هناك 4 حالات مختلفة: **requested**, **approved**, **acknowledged**, **confirmed executed**. لا تُخلط عند تشغيل أي جهاز.
- الأعطال والإخطارات تسجل الاستلام والإقرار والمعالجة والإغلاق والمستخدم والوقت.
- نتائج المعاينة الميدانية وصور التشغيل تحافظ على File Hash والأصل وتاريخ الرفع.
- كل جهاز خارجي له سجل صحة الاتصال والتأخر والقراءات غير الموثوقة.

## 5. نقاط اعتماد لاحقة
عتبات صلاحيات المشتريات، متى يصبح المشرف معتمداً، الصلاحيات البيطرية، ظروف إيقاف التغذية، حدود مناخ الصوب، إنذار الأكسجين، درجات حرارة التخزين، مدة الاحتفاظ بالبيانات، وخطة الاستجابة لكل حالة؛ لا يتم نسخ حدود عامة من الإنترنت لتكون برنامج تحكم فعلي.


## WF-17 — دورة قطيع الطيور والحمام (v0.4)
1. تعريف نوع الطائر وسلالته ومبناه وحدود الإيواء.
2. إنشاء دفعة/قطيع مع هدف الإنتاج، وتسجيل الطيور المعلمة فرديًا إن وجدت.
3. للحمام: إنشاء زوج تربية، عش، مجموعة بيض، وفترة حضانة ونتيجة الفقس.
4. للدجاج البياض: تسجيل الجمع والفرز والبيض المرسل للبيع/التفريخ ثم مراجعة الأعداد.
5. للتسمين: تسجيل التغذية، العينات الوزنية، النفوق، والعلاج والسحب ثم الحصاد.
6. كل صرف مخزن أو مبيعات تصبح مستند ERPNext معتمدًا منفصلًا؛ **السجلات الحالية لا تقوم بترحيل تلقائي**.
7. تنفذ الجرد والتسوية وفترات الحظر والتحصينات وفق Workflow خاص بعد اعتماده واختباره.

## WF-18 — آلية الرفع من الهاتف (منفذة جزئيًا)
يخزن الهاتف أحداث `WFM Field Log` محليًا بهوية UUID v4 ويعرض انتظار/نجاح/تعارض. ينشئ API مستند Draft فقط بعد تحقق صلاحيات المزرعة، ويتجاهل المحاولة المطابقة المكررة. لا يحوّل الحدث إلى ERPNext Stock Entry أو GL Entry، ولا يرسل أي أمر معدات. يحتاج أمن الجهاز والتحقق الحقيقي على Bench قبل الإنتاج.
